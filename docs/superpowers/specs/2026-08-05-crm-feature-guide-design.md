# CRM Feature Guide — Design

**Date:** 2026-08-05
**Deliverable:** `docs/client-materials/PROTON - CRM Feature Guide.docx`
**Audience:** Proton operators (agents + admins). User-guide tone, no code internals.
**Language:** English. **Format:** Word .docx built from the client template
(`docs/client-materials/Google Docs template - Short version.docx` styles),
generated by a `build_*.py` script like the existing proposal builders.
**Screenshots:** captured from the live Proton VM tenant via browser
automation (user logged in as admin in Chrome).

## Structure (Approach A — menu-mirror)

The document follows the CRM sidebar 1:1 so operators can look features up
the same way they see them on screen. Two cross-cutting chapters at the end
cover multi-feature journeys and integrations.

### Per-feature section template (fixed)

1. **What it is** — 2–4 sentence definition and purpose.
2. **Where to find it** — sidebar path / breadcrumb.
3. **How to use it** — numbered step-by-step instructions.
4. **Example scenario** — a short realistic Proton use case.
5. **Integrations & automation** — what other features/systems it touches
   (only when applicable).
6. **Screenshot** — one annotated capture (more for multi-step flows).

### Chapter outline (draft — exact labels verified against live UI during capture)

1. **Introduction** — what the platform is, logging in, screen layout,
   roles (agent vs administrator), language toggle (EN/ID).
2. **Conversations** — inbox views, All-conversations default tab,
   statuses (incl. default "All" filter), assignment, labels, priorities
   (incl. agent-priorities enhancement), private notes, canned responses,
   macros, mentions, **AI Copilot panel** (Ask Copilot, suggested replies,
   KB sources), **AI auto-draft / suggest-vs-auto mode** (what operators
   see and how to accept/edit), contact side panel, **DMS integration card**
   (vehicle/service data on the conversation), conversation actions
   (resolve, snooze, transcripts).
3. **Contacts** — contact list, profiles, conversation history, notes,
   segments; **Customer 360** lookup by phone / vehicle number.
4. **Knowledge** — FAQs (incl. bulk CSV upload), Documents (uploads),
   Assistants, Scenarios, Playground, Tools, Inboxes (assignment),
   Settings (persona, language, lifecycle messages, guardrails).
5. **Cases** — case list, case categories hierarchy, case lifecycle,
   how cases relate to conversations.
6. **RSA Incident Log** — logging roadside-assistance incidents, fields,
   statuses, how it feeds Customer 360 and reports.
7. **Reports** — native overview/CSAT/agent/label/inbox reports, the
   Proton reporting extensions (Agent reports, Department reports, Case
   list report), **Weekly Report** page, SLA reporting; dealer escalation
   turnaround stamping (what the timestamps mean).
8. **Campaigns & Help Center** — brief native coverage (one-off + ongoing
   campaigns; help-center portal basics).
9. **Administration (Settings)** — Agents, Teams, Inboxes (incl.
   inactivity-timing enhancement), Labels, Custom Attributes, Automation,
   Macros, Canned Responses, Integrations, **SLA Policies**, **Audit Log**,
   **Roles & Permissions**, **Escalation Routing** (PIC per department,
   dealer directory), FAQ Admin, account settings.
10. **AI assistant behaviour** — operator-facing explanation of the bot:
    when it replies vs hands off, escalation labels (`escalate`,
    `dealer_<slug>`), the two-thread escalation email (EM-7), lifecycle
    messages, phone/IVR touchpoint.
11. **End-to-end scenarios** — 5–7 walkthroughs spanning features, e.g.:
    WhatsApp inquiry → AI draft → agent send → resolve; complaint →
    escalate label → PIC/dealer email → turnaround report; RSA call →
    incident log → Customer 360; new FAQ batch → CSV upload → Playground
    test → live bot answer; weekly reporting routine.
12. **Integration overview** — one table + short prose per integration:
    WhatsApp, Email (incl. escalation emails), Phone/IVR, Gemini AI,
    DMS, Knowledge/Vertex corpus, BI/reporting exports.
- **Appendix** — glossary of terms (handoff, SLA, PIC, DMS, RSA…).

Native-only menus get concise coverage; custom features get full depth.

## Production pipeline

1. **Content research & drafting** — enumerate exact feature behaviour from
   fork patches (0001–0045), `agent/` services, and backend routers;
   draft each chapter as markdown working files in the scratchpad.
   Subagents fan out per chapter; definitions must be grounded in the
   actual code/patches, not guessed.
2. **Screenshot capture** — one Claude-in-Chrome session against the live
   Proton tenant (admin login provided by user). Walk every menu/submenu,
   save numbered PNGs to `docs/client-materials/feature-guide-assets/`.
   Prefer views without real customer PII; where unavoidable, pick
   innocuous conversations. No destructive clicks (no deletes, no sends).
3. **Build script** — `docs/client-materials/build_crm_feature_guide.py`
   (python-docx): inspects the template's styles (fonts, colors, heading
   hierarchy), generates the full document with embedded screenshots,
   auto table of contents, cover page.
4. **Review** — self-review pass for accuracy vs code, then user review.

## Out of scope

- Developer/deploy documentation (README + CLAUDE.md already cover it).
- Bahasa Indonesia translation (possible follow-up).
- Chatwoot features hidden/stripped by the fork (enterprise cruft,
  security settings nav) — excluded so the doc matches what operators see.

## Risks / notes

- Screenshot session depends on VM tenant availability and admin login;
  content drafting proceeds independently, so screenshots can be slotted
  in last.
- Exact menu labels/order come from the live UI at capture time; the
  outline above is corrected then if the deployed version differs.
