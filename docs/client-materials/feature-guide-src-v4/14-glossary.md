# Glossary
<!-- TRAINING: audience=agent -->

## Terms

| Term | Definition |
|---|---|
| Handoff | When the AI assistant stops handling a conversation and reopens it for a human agent, either because it can't confidently help or because the customer needs a person. See the AI Assistant Behaviour chapter. |
| Escalation | Applying the `escalate` label to an Email-channel conversation, which automatically sends the customer an acknowledgement email and forwards the case details to the responsible PIC and/or dealer group. A dealer or PIC's reply is linked back onto the same case as a private note, with an AI-drafted customer reply beside it. Applying the same label on a WhatsApp, Web Chatbot, or phone conversation does not send anything — only an Email-channel conversation triggers this automatically. See the AI Assistant Behaviour chapter and the Conversations chapter's Escalation replies section. |
| Escalation reply | A dealer, PIC, or customer's emailed reply to an escalation, linked back onto its original case automatically — always as a private note, whether it's a dealer/PIC reply or a customer replying to their own acknowledgement email. See the Conversations chapter's Escalation replies section. |
| PIC (Person In Charge) | The named contact responsible for a department, who receives escalation notifications for that department. Managed under Escalation Routing in the Administration chapter. |
| Dealer group | A named group of one or more member email addresses that represents a dealer outlet for escalation purposes — every member receives the forward. Managed under Escalation Routing in the Administration chapter. |
| Dealer slug | The short, consistent identifier used in a dealer label (for example, one per dealer outlet) so a conversation can be attributed to a specific dealer group for escalation and turnaround reporting. See the Conversations chapter's Labels section. |
| SLA (Service Level Agreement) | The response- and resolution-time targets the CRM tracks per conversation, configured under SLA Policies in the Administration chapter and measured on the SLA reports page in the Reports chapter. A breach on the Email inbox posts a private note on the case and emails the department's PIC group — see the Conversations chapter's SLA breach alerts section. |
| CSAT (Customer Satisfaction) | The 1–5 satisfaction rating a customer gives after a conversation, whether it was handled by the AI assistant or a human agent, shown in the CSAT report. See the Reports chapter. |
| RSA (Roadside Assistance) | Breakdown, accident, and similar roadside callout support, recorded in the RSA Incident Log chapter. |
| DMS / TSP (Dealer Management System / Telematics Service Provider) | A dealer's own vehicle and service-history system. The CRM has a placeholder connection point for it inside Customer 360, but no live adapter has been built yet — today that block always reads "Not connected." See the Contacts and Integration Overview chapters. |
| IVR (Interactive Voice Response) | The phone system that answers incoming calls; in this CRM, calls are answered by the AI assistant using natural conversation rather than a traditional press-1 menu. See the AI Assistant Behaviour chapter's Voice bot behaviour section. |
| Web Chatbot | The website's live chat widget, connected as a channel and answered by the same AI assistant as WhatsApp, with plain-text replies and no requirement for a visitor to give contact details. See the Integration Overview chapter's Web chatbot section. |
| Persona | An assistant's configured name, instructions, tone, and language preference, set on the Assistants and Settings pages. See the Knowledge chapter. |
| Guardrails | Short rules an administrator adds to an assistant's persona that it must never break, enforced on top of its general instructions. See the Knowledge chapter's Settings section. |
| Lifecycle message | One of the automatic customer-facing messages sent at a specific point in a conversation — for example a welcome message, an idle warning, or a satisfaction survey prompt. See the AI Assistant Behaviour chapter's Lifecycle messages section. |
| Segment | A saved, reusable contact filter, so a frequently used search doesn't need to be rebuilt each time. See the Contacts chapter's Notes & segments section. |
| Macro | A saved sequence of actions (for example, apply a label, send a reply, resolve) that an agent can run in one click from an open conversation. See the Conversations chapter's Macros section and the Administration chapter. |
| Canned response | A pre-written reply snippet an agent can insert into a conversation instead of retyping a common answer. See the Conversations chapter's Canned responses section and the Administration chapter. |
| Agent-bot | The AI assistant's automatic handling of a conversation — deciding, on its own, whether to reply or hand off to a human. See the AI Assistant Behaviour chapter. |
| Translate | A reply-box action that translates a message into another language without leaving the conversation — the customer's last message into the agent's working language, or a drafted reply into the customer's. See the Conversations chapter's Translate section. |
| FAQ suggestion strip | A row of matching FAQ answers shown above the reply box as an agent works a conversation, drawn from the same FAQ entries and knowledge base that ground Suggest-a-reply and Ask Copilot. See the Conversations chapter's FAQ suggestion strip section. |
| Inbound alert | A toast notification that fires when a new customer message arrives, so an agent working elsewhere in the CRM doesn't miss it. A separate per-agent page for choosing sound/desktop notifications and other event types exists in the code but is not switched on for this tenant — today it's toast-only. See the Conversations chapter's Inbound alerts section. |
| Private note | An internal message on a conversation, visible only to agents and administrators, never the customer — also how an AI-suggested reply arrives for review. See the Conversations chapter's Private notes section. |
| Customer 360 | A single search that looks a customer up by phone number or vehicle number and brings together their contact record, conversations, RSA incidents, and — where a live connection exists — DMS/TSP vehicle history. See the Contacts chapter. |
| Case category | The main category and subcategory assigned to a conversation (for example, Aftersales / Service Operation) used to organize the Cases list and reporting. See the Cases chapter. |
| Case Taxonomy admin page | The dedicated administration page where Case Category, Case Subcategory, and Case Detail are maintained; a save here rewrites all three option lists in full and the change reaches the conversation's dropdowns immediately. Case Type and Vehicle Model aren't part of it and stay on the general Custom Attributes page. See the Cases chapter's Case categorisation section. |
| Audit log | A read-only, filterable record of case/ticket status changes — who changed what, and when. See the Administration chapter. |
| Role & permission | The base access level (Agent or Administrator) an account has, plus any specific administrative capabilities granted on top of it, such as managing escalation routing or viewing the audit log. See the Introduction and Administration chapters. |
| Agent status | An agent's own availability — Available, Busy, Offline, or a named status such as Lunch or Break that an administrator has added — set from the profile menu or the dedicated My status page. Some named statuses count as unavailable for routing, and mirror into the CRM's own Online/Busy/Offline so routing still behaves correctly. See the Administration chapter's Agent Availability & My Status section. |
| Agent Channel Priorities | A table on an inbox's Collaborators tab where an administrator sets each agent's primary channel plus any others they also handle, steering which agent automatic assignment picks first on that channel. See the Administration chapter's Inboxes section. |
| Weekly Report | A single report page that reconciles a week's case volume, department/PIC performance, SLA, and dealer-turnaround figures into one view for a recurring reporting routine. See the Reports chapter. |
